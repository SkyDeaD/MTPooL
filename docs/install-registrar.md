# Установка регистратора

Регистратор — один сервис `mtpool-registrar`. Эта страница ведёт от пустого сервера до работающей панели: установка, имя пула, Cloudflare, ключи сенсоров, домены.

## Что понадобится

- Сервер с Ubuntu 24.04 (x86_64 или aarch64) и root-доступом. Скрипт установки другие системы отклоняет.
- Имя пула, например `pool.example.com`. Это адрес самого регистратора: **запись A на IP сервера создаётся вручную** в DNS. Пул её не создаёт и не меняет. Не включайте это имя в список доменов пула (см. ниже): домены пула пул переписывает сам.
- Зона в Cloudflare для доменов, которые будут отдаваться клиентам, и API-токен с правом править DNS этой зоны.
- Порты 80 и 443 на сервере открыты: Caddy получает сертификат для имени пула.
- Копия каталога `deploy/` из репозитория: юниты и `Caddyfile` скрипт читает рядом с собой.

## Установка

1. Склонируйте репозиторий и перейдите в него. Адрес репозитория — тот, из которого вы читаете эту страницу.

   ```bash
   git clone <адрес-репозитория> mtpool
   cd mtpool
   ```

2. Запустите скрипт от root. `--domain` обязателен.

   ```bash
   sudo sh deploy/install-registrar.sh --domain pool.example.com
   ```

   Открытый ключ подписи релизов скрипт берёт из `deploy/minisign.pub` рядом с собой. Скрипт скачивает манифест релиза и его подпись, проверяет подпись `minisign`, затем контрольную сумму бинарника. При несовпадении ничего не устанавливается.

3. Скопируйте админ-токен из последних строк вывода. Он показывается один раз.

Что делает скрипт: создаёт пользователя `mtpool` и каталоги `/etc/mtpool`, `/var/lib/mtpool`, `/var/backups/mtpool`; кладёт бинарник в `/usr/local/bin/mtpool-registrar`; ставит юниты systemd; при необходимости ставит Caddy из его репозитория и пишет `/etc/caddy/Caddyfile`; включает сокет и сервис регистратора, ежедневную резервную копию и путь самообновления.

### Параметры скрипта

| Параметр | Назначение |
|---|---|
| `--domain <имя>` | публичное имя пула, нужен полный домен вида `pool.example.com` (обязателен) |
| `--binary <путь>` | поставить свой бинарник вместо скачивания релиза; ключ не нужен |
| `--no-caddy` | не ставить Caddy; регистратор слушает только `127.0.0.1:8080`, свой прокси с TLS нужен перед ним |
| `--release-url <url>` | откуда скачивать релиз; по умолчанию `https://github.com/SkyDeaD/MTPooL/releases/latest/download` |
| `--release-repo <владелец/имя>` | репозиторий GitHub, откуда регистратор обновляет себя; пишется в `registrar.env` при первой установке |
| `--pubkey <ключ>` | другой открытый ключ подписи: base64-строка из файла `.pub`; по умолчанию ключ из `deploy/minisign.pub` |

Повторный запуск на сервере с базой считается обновлением: бинарник заменяется, сервис перезапускается, токен администратора не меняется.

## Проверка

```bash
curl -s https://pool.example.com/healthz
curl -s https://pool.example.com/readyz
```

Оба адреса отвечают `ok` с кодом 200. Затем откройте `https://pool.example.com/panel/` и войдите админ-токеном.

Потерян токен: выпустите новый на сервере.

```bash
sudo runuser -u mtpool -- mtpool-registrar admin reset-token
```

## Настройка пула

Настройки меняются в панели (`/panel/`) или через `PATCH /api/v1/admin/settings` с админ-токеном. Они применяются без перезапуска. Неверное значение отклоняется целиком, ничего не меняется.

### Ключи сервисов

Ключей три; без ключа сенсор отвечает `Abstain` с причиной «не настроен» (подробности в [sensors.md](sensors.md)).

| Секрет | Переменная окружения | Для чего |
|---|---|---|
| `cloudflare_api_token` | `CLOUDFLARE_API_TOKEN` | DNS-записи пула |
| `globalping_token` | `GLOBALPING_TOKEN` | замеры Globalping от регистратора |
| `redflag_api_key` | `REDFLAG_API_KEY` | сенсор RedFlag |

Значение, заданное в панели, главнее переменной окружения. Секреты в панели только записываются: прочитать их нельзя, API показывает лишь, задан ли секрет. Переменные окружения кладут в `/etc/mtpool/registrar.env` (строки `ИМЯ=значение`), после правки перезапустите сервис: `sudo systemctl restart mtpool-registrar`.

Токен Cloudflare выдайте только на зону доменов пула и только с правом редактировать DNS.

### Домены и DNS

Основные настройки (имена полей как в API):

| Поле | По умолчанию | Смысл |
|---|---|---|
| `domains` | пусто | домены пула; без повторов, без пустых имён |
| `proxy_port` | 443 | порт прокси на нодах; нода с другим портом в пул не входит |
| `tls_domain` | пусто | SNI, которым нода маскирует трафик |
| `proxy_users` | пусто | пользователи прокси: `name` (до 64 латинских букв, цифр, `-` и `_`) и `secret_hex` (32 hex-символа). В панели: **Настройки → Прокси** |
| `masters_per_domain` | 1 | мастеров на домен, от 1 до 8 |
| `rotation_ttl_sec` | 1800 | как часто менять мастера; 0 выключает ротацию, максимум 43200 |
| `dns_ttl` | 60 | TTL записей, от 60 до 86400; меньшие значения отклоняются |
| `dns_proxied` | `false` | оставьте `false`: MTProto не работает через прокси Cloudflare |

Как пул обращается с зоной:

- Каждая запись пула получает в Cloudflare комментарий `MTPooL`.
- Пул читает записи только под именами своих доменов. Остальные записи зоны он не читает и не меняет.
- Удаляет пул только записи типов A, AAAA и CNAME с комментарием ровно `MTPooL`. Запись с тем же именем, созданную вручную, он не удалит.

Пример: задать домены и параметры через API. Токен берите из переменной окружения, не из командной строки с историей.

```bash
curl -s -X PATCH https://pool.example.com/api/v1/admin/settings \
  -H "Authorization: Bearer $MTPOOL_ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"domains":["mt.example.com"],"tls_domain":"tls.example.com"}'
```

Ответ — весь документ настроек и карта `secrets` (задан секрет или нет). Секрет задаётся так: `{"secrets":{"cloudflare_api_token":"<токен>"}}`; `null` вместо значения стирает секрет.

### Автомасштабирование доменов (СРМД)

Для СРМД достаточно одного домена в `domains`, например `mt.example.com`. Остальные пул создаёт сам: при 6 здоровых нодах появится `mt1.example.com`, при 11 — `mt2.example.com` (по умолчанию 5 нод на домен и 1 мастер). Домены с номерами вручную вписывать не нужно.

По умолчанию выключено (`srmd.enabled: false`). Описание — в [lifecycle.md](lifecycle.md#срмд-автомасштабирование-доменов). Одна ловушка с именами описана в [operations.md](operations.md#имена-новых-доменов-срмд).
