# Подключение ноды

Нода — сервер с MTProto-движком и агентом `mtpool-agent`. Установщик ставит агента (и при желании движок), проверяет подпись релиза и записывает токен регистрации.

## Что понадобится

- Регистратор по [установке](install-registrar.md) и вход в панель.
- Сервер с Ubuntu или Debian, root-доступ, публичный IP. Установщик другие системы отклоняет.
- В настройках пула заданы `tls_domain` и `proxy_port` (по умолчанию 443). Установщик получает их от регистратора.
- Движок: telemt, MTProxyL или MEKO. Если на сервере его нет, установщик поставит telemt или MTProxyL по флагу `--preset`.

## Токен регистрации

Нода входит в пул по токену регистрации (`enroll`), который принадлежит владельцу. У владельца есть лимит нод (`node_limit`). Создайте владельца и токен в панели или через API.

```bash
curl -s -X POST https://pool.example.com/api/v1/admin/owners \
  -H "Authorization: Bearer $MTPOOL_ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"alpha","node_limit":3}'

curl -s -X POST https://pool.example.com/api/v1/admin/tokens \
  -H "Authorization: Bearer $MTPOOL_ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"kind":"enroll","owner_id":1}'
```

Ответ на второй запрос содержит поле `token` с префиксом `mtp_enroll_`. Значение показывается один раз. Токен можно ограничить по сроку: поле `expires_at` (RFC 3339).

## Установка

1. Сохраните токен в файл с доступом только для root, чтобы он не попал в историю команд и список процессов. Команда ждёт ввода: вставьте токен, нажмите Enter, затем Ctrl-D.

   ```bash
   sudo sh -c 'umask 077; cat > /root/mtpool.token'
   ```

2. Запустите установщик. Регистратор раздаёт его по адресу `/install.sh`, уже с адресом пула и открытым ключом.

   ```bash
   curl -fsSL https://pool.example.com/install.sh | sudo sh -s -- --name node1 --token-file /root/mtpool.token
   ```

   Вместо файла можно передать токен переменной окружения, как в примере из README: `sudo env MTPOOL_TOKEN=<токен> sh -s -- --name node1`. Тогда значение останется в истории команд. Аргументом токен передать нельзя: аргументы видны в `ps`.

3. Если движка нет, добавьте `--preset telemt` или `--preset mtproxyl` (MTProxyL приносит свой telemt). Установщик скачивает движок фиксированной версии и сверяет контрольную сумму.

4. Следите за шагами на экране: система, инструменты, релиз, движок, агент, регистрация, проверка пулом. Установщик ждёт, пока пул примет ноду и признает её `Healthy`. В конце он показывает ссылку на страницу ноды и команды для логов.

   | Итог | Код выхода | Что это значит |
   |---|---|---|
   | `Готово: <id> здорова и работает в пуле.` | 0 | нода работает |
   | `Нода установлена, пул ещё проверяет её.` | 0 | за 3 минуты проверка не закончилась, пул продолжит сам |
   | `пул не принял ноду за 60 с` | 1 | проверьте токен и доступ к адресу пула, агент продолжит пытаться сам |
   | `пул заблокировал IP этой ноды` | 1 | IP ноды заблокирован в пуле |

   `Ctrl+C` на шаге проверки пулом прерывает только ожидание: нода уже установлена.

### Параметры установщика

| Параметр | Назначение |
|---|---|
| `--name <имя>` | имя ноды: латинские буквы, цифры, `.`, `-`, `_`, не длиннее 32 символов, начинается и заканчивается буквой или цифрой (обязателен) |
| `--token-file <путь>` | прочитать токен из файла вместо `MTPOOL_TOKEN` |
| `--preset telemt\|mtproxyl` | поставить движок |
| `--port <n>` | порт движка, если его нельзя прочитать из конфигурации |

### Где смотреть логи

| Что | Где |
|---|---|
| Журнал агента | `journalctl -u mtpool-agent -f` |
| Состояние службы | `systemctl status mtpool-agent` |
| Вывод установщика и программ, которые он запускал | `/var/log/mtpool/install.log`, доступен только root |

Без терминала (`| tee`, CI) установщик пишет простые строки без цвета и анимации. Переменная `NO_COLOR` отключает цвет.

### Что проверяет установщик

- Подпись манифеста релиза (`minisign`) открытым ключом пула, затем контрольную сумму бинарника агента. При несовпадении ничего не устанавливается.
- Версию релиза. Если релиз на пуле новее его регистратора, установка останавливается: регистратор откатился или вот-вот перезапустится, а более старой сборки агента на пуле нет. На сервере ничего не меняется, повторите команду, когда регистратор обновится.
- Порт движка. Если он не совпадает с `proxy_port` пула, установка завершается ошибкой: поменяйте порт движка или настройку пула.
- Движок ищется по файлам: `/opt/mtpr-simple` — MEKO, `/opt/mtproxyl` — MTProxyL, иначе telemt (`/etc/telemt/telemt.toml`). MEKO только определяется, ставить его `--preset` нельзя.

Что остаётся на сервере: бинарник `/usr/local/bin/mtpool-agent`, юниты `mtpool-agent` и `mtpool-agent-rollback`, настройки `/etc/mtpool/agent.toml`, состояние в `/var/lib/mtpool/` (каталог 0700, файлы 0600).

## Настройки агента

Файл `/etc/mtpool/agent.toml` создаёт установщик. Неизвестные ключи отвергаются.

| Ключ | Смысл |
|---|---|
| `registrar` | адрес регистратора, `https://...`; `http` допустим только для loopback |
| `name` | имя ноды |
| `state_dir` | каталог состояния; по умолчанию `/var/lib/mtpool` |
| `port` | порт прокси; если ключа нет, его сообщает адаптер движка |
| `antiscan` | `true` включает защиту от сканеров (список ipsum, ipset и цепочка iptables); установщик пишет `true` и ставит `ipset` и `iptables` |
| `check_host_port` | порт, который сервис check-host проверяет с двух точек в Москве, чтобы узнать, закрыт ли адрес ноды из РФ; по умолчанию 22. `0` отключает проверку: регистратор получает «отключено», и голос check-host не учитывается |
| `[intervals]` | `heartbeat_sec`, `globalping_sec`, `metrics_sec`, `sync_sec`: действуют, пока регистратор не вернёт настройки |

Ставьте `check_host_port = 0` там, где SSH закрыт фаерволом для РФ или снаружи вообще недоступен: иначе проверка покажет закрытый порт, а не блокировку адреса. Агент сам обращается к check-host.net с адреса ноды не чаще раза в 5 минут и только когда регистратор просит; адрес сервиса можно заменить переменной `MTPOOL_CHECK_HOST_URL` (нужно только тестовому стенду).

Интервалы по умолчанию: heartbeat 15 секунд, Globalping 300, метрики 60, синхронизация 60. Их можно менять для всего пула в настройках регистратора.

На ноде, установленной раньше, этих пакетов может не быть. Тогда защита от сканеров не работает, а в журнале агента есть `antiscan: the old list stays` с ошибкой `ipset: No such file or directory`. На работу прокси это не влияет. Поставьте пакеты:

```bash
sudo apt-get install -y ipset iptables
```

Агент повторит попытку сам в течение 5 минут, перезапускать его не нужно. В журнале появится `antiscan list in place`.

## Как агент обращается с конфигурацией движка

Агент дополняет конфигурацию владельца сервера, а не перезаписывает её.

- Пул добавляет своих пользователей рядом с вашими и удаляет только тех, кого добавил сам.
- В клиенты и трафик пула идут только его пользователи. Ваши показываются отдельно.
- Если у вас уже есть пользователь с именем из настроек пула и другим секретом, агент не применяет конфигурацию пула: движок не перезапускается, ваш пользователь и его клиенты работают как раньше, а нода в пул не входит. Что делать, описано в разделе [Если нода не входит в пул](#если-нода-не-входит-в-пул).
- Пользователь с тем же именем и тем же секретом считается пользователем пула, потому что запись в движке одна. Его клиенты и трафик идут в статистику пула.
- `tls_domain` записывается, только если ключа нет. Существующее значение не меняется.
- Порт агент не меняет. Нода с другим портом сообщает его, получает `port_ok = false` и в пул не входит; её собственная ссылка продолжает работать.
- Если менять нечего, файл не перезаписывается и движок не перезапускается.
- Для telemt любое изменение пользователей или доменов делается перезапуском службы. Если после перезапуска telemt не ответил на метрики, предыдущая конфигурация возвращается.
- MTProxyL настраивается только его командами (`mtproxyl secret`, `mtproxyl expert`, `mtproxyl restart`): простой `systemctl restart` поднял бы старую конфигурацию.

Предупреждение для MTProxyL: у него есть ограничение nft примерно в одно новое соединение в секунду с одного источника. Если поставить `tcp_probe_interval_sec` меньше 2 секунд (по умолчанию 5), проверки регистратора начнут резаться, и такие ноды будут выпадать из пула.

## Если нода не входит в пул

Смотрите журнал агента на ноде и список нод в панели.

```bash
journalctl -u mtpool-agent -n 100 --no-pager
systemctl status mtpool-agent
```

- Установщик остановился на шаге «Релиз» со словами «на пуле пока нет релиза»: регистратор ещё не скачал релиз. Повторите установку через минуту. Если не помогло, проверьте релиз на регистраторе: [install-registrar.md](install-registrar.md#релиз-для-нод).
- Отчёт `403` с причиной в журнале: нода снята пулом. Агент перестаёт слать отчёты и повторяет регистрацию раз в 15 минут, а если у сервера сменился адрес, то сразу.
- Токен ноды недействителен: агент удаляет файл и регистрируется заново токеном регистрации. Если и тот отозван, агент останавливается с понятной ошибкой в журнале. Так выглядит и бан: вместе с записью ноды удаляется её токен.
- Регистрация получает 429 с `Retry-After`: IP заблокирован или на паузе. После бана первая новая проверка возможна через `reverify_pause_sec` (15 минут). Причину смотрите в истории банов. Если адрес сервера сменился, агент не ждёт конца паузы.
- Регистрация получает `403 owner_limit`: лимит нод владельца занят живыми нодами. Снимите лишнюю ноду, или новая нода войдёт сама, когда одна из старых промолчит 60 секунд. Подробнее: [lifecycle.md](lifecycle.md#лимит-нод-владельца).
- Порт не совпадает с `proxy_port`: нода остаётся вне пула.
- В журнале агента `the owner's configuration already has the users`, в панели причина карантина «на ноде уже есть пользователь с именем из настроек пула и другим секретом». Переименуйте своего пользователя в конфигурации движка и перезапустите движок (для MTProxyL через его команды) или смените имя в `proxy_users` в настройках пула. Секрет менять не нужно: в ссылке клиента есть только секрет, имени в ней нет. Агент сам применит конфигурацию при следующей синхронизации, и нода вернётся в пул. Если нода пробудет в карантине дольше `quarantine_max_sec` (час), она станет `Pruned`: агент будет повторять регистрацию, а пул отвечать 429 с растущей паузой. После исправления нода войдёт в пул при следующей принятой регистрации.

Подробнее о состояниях: [lifecycle.md](lifecycle.md). Общая диагностика: [operations.md](operations.md#диагностика).

## Вывод ноды из пула

- Владелец: `POST /api/v1/me/nodes/{id}/retire` токеном бота или кнопкой в панели.
- Администратор: `POST /api/v1/admin/nodes/{id}/retire`.
- Нода сама вызывает `/api/v1/agent/retire`, если прокси на ней 10 минут подряд неисправен.
