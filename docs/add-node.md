# Подключение ноды

Нода — сервер с MTProto-движком и агентом `mtpool-agent`. Установщик ставит агента (и при желании движок), проверяет подпись релиза и записывает токен регистрации.

## Что понадобится

- Регистратор по [установке](install-registrar.md) и вход в панель.
- Сервер с Ubuntu или Debian, root-доступ, публичный IP. Установщик другие системы отклоняет.
- В настройках пула заданы `tls_domain` и `proxy_port` (по умолчанию 443). Установщик получает их от регистратора.
- Движок: telemt, MTProxyL или MEKO. Если на сервере его нет, установщик поставит telemt или MTProxyL по флагу `--preset`.

## Токен регистрации

Нода входит в пул по токену регистрации (`enroll`), который принадлежит владельцу. У владельца есть лимит нод (`node_limit`). Создайте владельца и токен в панели или через API.

```bash
curl -s -X POST https://pool.example.com/api/v1/admin/owners \
  -H "Authorization: Bearer $MTPOOL_ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"alpha","node_limit":3}'

curl -s -X POST https://pool.example.com/api/v1/admin/tokens \
  -H "Authorization: Bearer $MTPOOL_ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"kind":"enroll","owner_id":1}'
```

Ответ на второй запрос содержит поле `token` с префиксом `mtp_enroll_`. Значение показывается один раз. Токен можно ограничить по сроку: поле `expires_at` (RFC 3339).

## Установка

1. Сохраните токен в файл с доступом только для root, чтобы он не попал в историю команд и список процессов. Команда ждёт ввода: вставьте токен, нажмите Enter, затем Ctrl-D.

   ```bash
   sudo sh -c 'umask 077; cat > /root/mtpool.token'
   ```

2. Запустите установщик. Регистратор раздаёт его по адресу `/install.sh`, уже с адресом пула и открытым ключом.

   ```bash
   curl -fsSL https://pool.example.com/install.sh | sudo sh -s -- --name node1 --token-file /root/mtpool.token
   ```

   Вместо файла можно передать токен переменной окружения, как в примере из README: `sudo env MTPOOL_TOKEN=<токен> sh -s -- --name node1`. Тогда значение останется в истории команд. Аргументом токен передать нельзя: аргументы видны в `ps`.

3. Если движка нет, добавьте `--preset telemt` или `--preset mtproxyl` (MTProxyL приносит свой telemt). Установщик скачивает движок фиксированной версии и сверяет контрольную сумму.

4. Дождитесь строки `done: node1 is installed and enrolls with ...`. Нода появляется в панели в состоянии `Pending` и становится `Healthy` после первого верного отчёта.

### Параметры установщика

| Параметр | Назначение |
|---|---|
| `--name <имя>` | имя ноды: буквы, цифры, `.`, `-`, `_`, не длиннее 63 символов (обязателен) |
| `--token-file <путь>` | прочитать токен из файла вместо `MTPOOL_TOKEN` |
| `--preset telemt\|mtproxyl` | поставить движок |
| `--port <n>` | порт движка, если его нельзя прочитать из конфигурации |

### Что проверяет установщик

- Подпись манифеста релиза (`minisign`) открытым ключом пула, затем контрольную сумму бинарника агента. При несовпадении ничего не устанавливается.
- Порт движка. Если он не совпадает с `proxy_port` пула, установка завершается ошибкой: поменяйте порт движка или настройку пула.
- Движок ищется по файлам: `/opt/mtpr-simple` — MEKO, `/opt/mtproxyl` — MTProxyL, иначе telemt (`/etc/telemt/telemt.toml`). MEKO только определяется, ставить его `--preset` нельзя.

Что остаётся на сервере: бинарник `/usr/local/bin/mtpool-agent`, юниты `mtpool-agent` и `mtpool-agent-rollback`, настройки `/etc/mtpool/agent.toml`, состояние в `/var/lib/mtpool/` (каталог 0700, файлы 0600).

## Настройки агента

Файл `/etc/mtpool/agent.toml` создаёт установщик. Неизвестные ключи отвергаются.

| Ключ | Смысл |
|---|---|
| `registrar` | адрес регистратора, `https://...`; `http` допустим только для loopback |
| `name` | имя ноды |
| `state_dir` | каталог состояния; по умолчанию `/var/lib/mtpool` |
| `port` | порт прокси; если ключа нет, его сообщает адаптер движка |
| `antiscan` | `true` включает защиту от сканеров (список ipsum, ipset и цепочка iptables); установщик пишет `true` |
| `[intervals]` | `heartbeat_sec`, `globalping_sec`, `metrics_sec`, `sync_sec`: действуют, пока регистратор не вернёт настройки |

Интервалы по умолчанию: heartbeat 15 секунд, Globalping 300, метрики 60, синхронизация 60. Их можно менять для всего пула в настройках регистратора.

## Как агент обращается с конфигурацией движка

Агент дополняет конфигурацию владельца сервера, а не перезаписывает её.

- Пул добавляет своих пользователей рядом с вашими и удаляет только тех, кого добавил сам.
- `tls_domain` записывается, только если ключа нет. Существующее значение не меняется.
- Порт агент не меняет. Нода с другим портом сообщает его, получает `port_ok = false` и в пул не входит; её собственная ссылка продолжает работать.
- Если менять нечего, файл не перезаписывается и движок не перезапускается.
- Для telemt любое изменение пользователей или доменов делается перезапуском службы. Если после перезапуска telemt не ответил на метрики, предыдущая конфигурация возвращается.
- MTProxyL настраивается только его командами (`mtproxyl secret`, `mtproxyl expert`, `mtproxyl restart`): простой `systemctl restart` поднял бы старую конфигурацию.

Предупреждение для MTProxyL: у него есть ограничение nft примерно в одно новое соединение в секунду с одного источника. Если поставить `tcp_probe_interval_sec` меньше 2 секунд (по умолчанию 5), проверки регистратора начнут резаться, и такие ноды будут выпадать из пула.

## Если нода не входит в пул

Смотрите журнал агента на ноде и список нод в панели.

```bash
journalctl -u mtpool-agent -n 100 --no-pager
systemctl status mtpool-agent
```

- Отчёт `403` с причиной в журнале: нода снята пулом (например, забанена). Агент перестаёт слать отчёты и повторяет регистрацию раз в 15 минут.
- Токен ноды недействителен: агент удаляет файл и регистрируется заново токеном регистрации. Если и тот отозван, агент останавливается с понятной ошибкой в журнале.
- Порт не совпадает с `proxy_port`: нода остаётся вне пула.

Подробнее о состояниях: [lifecycle.md](lifecycle.md). Общая диагностика: [operations.md](operations.md#диагностика).

## Вывод ноды из пула

- Владелец: `POST /api/v1/me/nodes/{id}/retire` токеном бота или кнопкой в панели.
- Администратор: `POST /api/v1/admin/nodes/{id}/retire`.
- Нода сама вызывает `/api/v1/agent/retire`, если прокси на ней 10 минут подряд неисправен.
