# Сенсоры

Сенсор отвечает на вопрос «блокируют ли этот IP из России». Голос сенсора — одно из трёх значений:

| Голос | Смысл |
|---|---|
| `Blocked` | сенсор видит блокировку |
| `Clear` | сенсор видит, что всё работает |
| `Abstain` | сенсор не может судить; не голос |

Правила, которые не зависят от сенсора:

- Бан требует не меньше двух голосов `Blocked`. Число сенсоров на это правило не влияет.
- Ключ не задан, ошибка, таймаут, превышен лимит или ответ незнаком — всегда `Abstain`. Неисправный сенсор никогда не голосует за бан.
- Каждый голос сохраняет доказательство. В панели оно видно на странице ноды, а в публичном API — в `last_round`.

Сенсоров три: Globalping, Cheburcheck и RedFlag. Как голоса превращаются в решение, описано в [lifecycle.md](lifecycle.md).

## Globalping

Измерение с проб в российских домашних сетях: HTTPS-запрос `HEAD` на IP ноды с SNI ноды. Проба успешна, если рукопожатие TLS прошло. HTTP-код не важен: ответ 403 после рукопожатия считается успехом. Если сертификат не принимается, проба всё равно хранит данные TLS с `authorized: false`, поэтому такая проба считается успешной.

- Плановые замеры делает сам агент, на лимит своего IP: при интервале 300 секунд это 12 замеров по 20 проб в час. Анонимный лимит считается по адресу, а для IPv6 один счётчик на всю /64, поэтому агент обращается к API Globalping только по IPv4. Регистратор скачивает результат и проверяет его сам: id, тип, цель, порт, SNI, страну каждой пробы, число проб и время создания. Отчёт вне окна от −10 до +1 минуты отвергается, один `measurement_id` нельзя использовать дважды.
- Голос раунда берётся из верного отчёта агента младше 10 минут. Если такого нет, замер создаёт регистратор токеном `globalping_token`.
- Токен Globalping на ноды не передаётся: иначе все ноды делили бы один лимит аккаунта.
- **Лимит 500 тестов в час общий для всех токенов одного аккаунта.** Сверх лимита Globalping может списывать кредиты. Перед своим замером регистратор смотрит остаток лимита (бесплатный запрос). Если остаток меньше `globalping.min_limit_remaining` (20), сенсор отвечает `Abstain` и кредиты не тратит, пока `globalping.allow_credits` равно `false` (так по умолчанию).
- Первый замер агент делает сразу после регистрации. Готовый замер он отправляет ближайшим тактом heartbeat, не дожидаясь очередного отчёта.
- Регистратор может попросить замер вне расписания: поле `measure_now` в ответе `GET /api/v1/agent/config`. Он просит, когда отчёт с замером старше интервала плюс минута или нода подозревается в блокировке. Агент переносит ближайший плановый замер на сейчас, но не раньше 5 минут после начала предыдущего и не раньше интервала после ответа 429. Расписание сдвигается, поэтому замеров по-прежнему не больше 12 в час.
- Ответ 429 от Globalping агент передаёт как «нет данных». Это не провал и не причина для карантина.
- Если больше половины проб с результатом получили отказ в соединении (`ECONNREFUSED`), голос `Abstain` с причиной `port_refused`: порт закрыт, это не блокировка. Для здоровья ноды такой замер означает «нет данных», закрытый порт и так видит проверка TCP. Ограничение: если блокировка по адресу станет отвечать отказом в соединении, Globalping её не увидит. Нода тогда останется вне очереди без раундов сенсоров и будет удалена через `quarantine_max_sec`, но не забанена.
- Отчёт без нового замера не меняет последний вердикт: агент отчитывается раз в минуту, а измеряет раз в 5 минут.

Настройки (раздел `globalping`):

| Поле | По умолчанию | Смысл |
|---|---|---|
| `probe_limit` | 20 | сколько проб просить |
| `min_probes` | 10 | проб с результатом меньше этого — `Abstain`; больше половины проб с результатом получили отказ в соединении — `Abstain` с причиной `port_refused` |
| `success_threshold` | 0.5 | доля успеха ниже порога — `Blocked`, иначе `Clear` |
| `vote_report_max_age_sec` | 600 | насколько свеж отчёт агента, чтобы стать голосом |
| `window_past_sec` / `window_future_sec` | 600 / 60 | допустимый возраст замера: в прошлое и в будущее |
| `min_limit_remaining` | 20 | меньший остаток лимита — `Abstain` |
| `allow_credits` | `false` | разрешить тратить кредиты |

## Cheburcheck

Регистратор запускает проверку IP ноды и читает поток результатов проб с бюджетом 90 секунд.

- Вердикты проб `tspu_block` и `sni_block` — блокировка, `ok` — чисто, `uncertain` не учитывается.
- Заблокированных больше половины учтённых проб — `Blocked`. Учтённых нет — `Abstain`.
- Быстрый флаг `blocked` в ответе в голосовании **не участвует**. Он срабатывает на сеть провайдера из списка (например, у крупных облаков он бывает `true`) и показывается в карточке ноды как подсказка.
- Лимитер: 4 пробы в минуту на весь пул.
- Возраст кэша ответ сервиса не сообщает, поэтому регистратор его не показывает и не учитывает.

Ключ не нужен.

## RedFlag

Проверка конкретного сервера: регистратор отправляет сервису IP ноды, порт и публичный секрет пула, ключ передаётся заголовком `X-API-Key`. Ключ — настройка `redflag_api_key` или переменная `REDFLAG_API_KEY`. Без ключа сенсор всегда отвечает `Abstain`.

| Статус сервиса | Голос |
|---|---|
| `OK` | `Clear` |
| `DATA_CUT` | `Blocked` |
| `RKN_BLOCK` | `Blocked` |
| `MT_DEAD` | `Abstain` |
| `DOWN` | `Abstain` |
| `UNKNOWN` и любой незнакомый статус | `Abstain` |

`MT_DEAD` и `DOWN` — неисправность сервера или сети снаружи, а не блокировка из России, поэтому они лишь показываются в карточке ноды. Коды ответа 401, 403, 429, 502, 503 и таймаут дают `Abstain`; при 429 соблюдается `Retry-After`. Лимитер пула — 20 запросов в минуту.

Точка проверки «из РФ» у сервиса одна. Блокировку только в мобильной сети он может не увидеть, поэтому его голос в одиночку бан не решает.

## Проверить, что сенсоры работают

- Панель, раздел статуса (`GET /api/v1/admin/status`): состояние внешних сервисов, DNS и счётчики за сутки и неделю.
- Страница ноды: голоса последнего раунда с причинами `Abstain`.
- Замера Globalping нет: строка `no Globalping measurement` с причиной в журнале агента и регистратора.
- Причина `not_configured` у голоса `abstain` означает, что ключ сенсора не задан. Причина `key_rejected` означает, что сервис не принял ключ (RedFlag ответил 401 или 403). Другие причины: `unavailable`, `rate_limited`, `timeout`, `unknown_answer`, `no_data`, `port_refused`.
